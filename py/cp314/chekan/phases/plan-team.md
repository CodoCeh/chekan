## План

Разбейте работу на задачи. У каждой задачи — исполнитель из команды и чек-лист: по нему проверяющий решит «принято» или «на доработку». Чек-лист увидит пользователь, поэтому пишите его простыми словами.

### Как заводить

```
chekan team
chekan task add 01 --title "Реестр должников" --requirements R01 --zone Готово/reestr/ --owner R3 \
    --check "долг = отгружено минус оплачено по каждой строке" \
    --check "у каждого должника срок оплаты и дни просрочки"
```

- **`--owner`** — номер участника из `chekan team`. Нужна роль, которой нет, — добавьте её: `chekan team add "<специальность>"`.
- **`--check`** — пункт чек-листа, по одному на флаг. Каждый пункт проверяем по самому результату: «письмо вежливое» плохо, «в письме сумма, срок и контакт для вопросов» хорошо.
- **`--zone`** — папка результата внутри «Готово». Две задачи в одной папке без зависимости столкнутся.
- **`--deps`** — задачи, которые закроются раньше.
- Команду проверки (`--verify`) задавайте только программисту и тестировщику: это след их инструмента.

### Гейт G3

Каждое требование ведёт к задаче, у каждой задачи есть исполнитель и чек-лист. Проверка: `chekan gate G3`. В режиме «Контроль» покажите план пользователю и получите «да» до `chekan advance`.
