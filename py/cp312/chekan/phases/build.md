## Разработка

Готово доказывается исполнением, а не записью: `done` ставит код возврата команды, а не ваше суждение. Без зелёного прогона CLI закрыть таск не даст.

### Цикл одного таска

1. `chekan task start NN --model <модель>` — `--model` обязателен: ни один харнесс не публикует имя модели, без флага в отчёте не будет, кто делал. Забыли — `chekan task set NN --model <…>`.
2. Запустите субагента со свежим контекстом. Первая строка его промпта — `[chekan-executor NN]`: по ней Antigravity пускает исполнителя писать код. Передайте **пути, а не текст**: `interfaces.md`, файл таска, нужные разделы спеки, команду проверки, рабочий каталог.
3. Вшейте в промпт исполнителя дословно три блока:
   - **Контракт возврата.** Не больше 25 строк, без кода и диффов, без вступлений и пересказа задачи: `STATUS: DONE | HANDOFF | BLOCKED` плюс `FILES / TESTS / INTERFACES / CONCERNS / TOKENS` (вход плюс выход за таск).
   - **Потолок контекста.** «Около семидесяти правок и прогонов — остановись на ближайшем зелёном прогоне и верни `STATUS: HANDOFF`». Раздутый контекст дорожает квадратично.
   - **Пульс.** «Каждые ~15–20 правок и перед долгим шагом: `chekan task note NN "<что делаешь>"`». Это не доказательство, а строка в состоянии: панель покажет, на чём исполнитель затих, и счётчик тишины сбросится.
4. Проверка: `chekan run "<команда>" --task NN`. Красная — чините, не закрывайте. Три и больше провала подряд на одном коде Чекан назовёт зацикливанием (в выводе и в Телеграме): меняйте подход, а не повторяйте команду.
5. **Код-ревью отдельным субагентом** — не тем, кто писал. Его промпт: `chekan prompt review --task NN`; его ответ-JSON приложите: `chekan review NN <файл.json>`. Находки — «недоделка» для того же исполнителя; после починки — снова `chekan run` и `chekan review NN --clear`. Находок нет — идите дальше. Неразобранные находки попадут в отчёт разделом «⚠ Ревью кода».
6. Закрытие: `chekan task done NN --tokens N`. CLI сверит, что доказательство снято на текущем коде. `--tokens` — строка `TOKENS` из отчёта исполнителя. Не назвали — Чекан поищет токены в журнале Claude Code и покажет их отдельно со словом «не измерен»; не нашёл — останется «не измерен», не ноль.
7. Коммит: **один на таск**, номер таска в заголовке, только пути таска: новые файлы — `git add <путь>`, затем `git commit -m "NN: …" -- <пути таска>`.

### Вопрос владельцу

Спрашивайте, только когда без ответа продолжать нельзя. Иначе решайте сами и запишите решение в заметку требования или таска как предположение. Вопрос — `chekan ask "<текст>"`; в режиме `auto` команда откажет.

### Параллель

Не больше **трёх исполнителей в полёте**. Волну запускайте **одним сообщением**: вызовы в разных сообщениях выполнятся последовательно. Зоны внутри волны не пересекаются — это проверил гейт G3.

Исполнитель волны коммитит **только свои пути**: `git commit -m "NN: …" -- <свои пути>` (новые файлы перед этим — `git add <путь>`). `git add -A` и `git commit -a` запрещены: уносят чужие незакоммиченные правки. Свой `GIT_INDEX_FILE` не используйте: без `git read-tree HEAD` такой коммит удаляет все чужие файлы. Оркестратор перед волной проверяет, что дерево чистое, а после закрытия — что в коммите ровно названное в отчёте.

### Ремонт — две адресации

**Недоделка** (красный тест, находка ревью): дозапрос **тому же субагенту** одной строкой. Не больше двух дозапросов.

**Отказ** (`BLOCKED`, повторно проваленный ремонт): свежий контекст и **другой подход**. Тот же промпт даст тот же результат.

Код проекта оркестратор не пишет никогда, даже как запасной вариант.

### Передача другому агенту

Владелец вправе остановить вас и уйти к другому агенту — тот продолжит через `chekan handoff`. Перед остановкой на `HANDOFF`/`BLOCKED` или на дорогом незакрытом таске оставьте записку: `chekan task note NN --handoff "сделано X, осталось Y, оборвался на Z"`. Записка — ввод в курс, **а не разрешение дописывать чужой код**: таск гонится с нуля до зелёного прогона.

### Если план не держится

Нарезка неверна — решаете вы, код по-прежнему пишет исполнитель. Поправьте спеку на месте, добавьте требование с суффиксом `D` (открытие, найденное сборкой), перенарежьте только то, что стало невалидным. Владельцу — одна строка в чате (не `chekan ask`) в любом режиме, включая `auto`.

### Претензия гейта — это список работы, а не остановка

Красный гейт — список следующих шагов, а не приговор. Закрывайте претензии по одной до зелёного: наша задача — зелёный прогон, а не аккуратно оформленная остановка.

Звать владельца можно в одном случае: претензия требует его решения. Тогда назовите её словами целиком («гейт G4, слепой приёмщик не нашёл вот это»), а не номером гейта. В `auto` — вопрос в чате, как в скилле («Развилка в `auto`»).

Модель: по задаче (`--model` обязателен) — рутинные таски дешёвым моделям, узкие места сильным.
