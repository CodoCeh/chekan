## Что это и когда брать

Лог (журнал работы программы) — файл, куда сервис пишет строку на каждое событие: запрос, предупреждение, ошибку. Разбор логов отвечает на вопросы «что сломалось, когда и с чего началось». Инструменты — стандартные `tail`, `grep`, `awk`, `sort`, `uniq`, а для JSON-логов — `jq` (утилита для JSON). Бери их, когда сервис ведёт себя странно, после выкладки и перед словами «ошибок нет».

Когда НЕ брать: логов нет или проблема воспроизводится тестом — тогда учебник `tests`. Лог с личными данными не копируй целиком в отчёт.

## Установка и проверка

```bash
grep --version | head -1 && jq --version
```

`grep`, `awk`, `tail` есть в любой системе. `jq` ставят одноимённым пакетом. Ставить что-либо — только после «да» пользователя.

## Порядок работы

1. Найди нужный лог и его ротации (старые части вида `app.log.1.gz`). Узнай формат строки: время, уровень, сообщение.
2. Сузь время: от последнего заведомо рабочего момента до жалобы.
3. Посчитай ошибки и сгруппируй по типу. Числа в сообщениях замени на `N`, иначе одинаковые ошибки не склеятся.
4. Найди ПЕРВУЮ ошибку в окне и посмотри контекст до неё. Первая ошибка обычно причина, последующие — следствия.
5. Прочитай полный traceback (стек вызовов при падении). Он идёт отдельными строками без даты.
6. Проверь гипотезу: после фикса следи за логом вживую через `tail -f` и убедись, что ошибка не повторяется.

## Готовые команды

Счёт и первая ошибка с контекстом (`-n` — номер строки, `-B`/`-A` — строки до и после):

```bash
grep -c " ERROR " app.log
grep -n -m1 -B2 -A5 " ERROR " app.log
grep -n " ERROR " app.log | head -1
grep -n " ERROR " app.log | tail -1
grep -n "Traceback" -A3 app.log | head -5
```

Группировка по уровню, типу и часу:

```bash
grep -E " (ERROR|WARNING) " app.log | awk '{print $3}' | sort | uniq -c
grep " ERROR " app.log | sed -E 's/[0-9]+/N/g' | cut -d' ' -f4- | sort | uniq -c | sort -rn | head
grep " ERROR " app.log | awk '{print substr($2,1,2)":00"}' | uniq -c
```

Окно по времени (строки с датой `ГГГГ-ММ-ДД ЧЧ:ММ:СС` сравниваются как текст):

```bash
awk '$1" "$2 >= "2026-11-15 11:40:00" && $1" "$2 < "2026-11-15 11:45:00"' app.log | grep " ERROR "
```

Сжатая ротация:

```bash
zgrep -c " ERROR " app.log.1.gz
```

JSON-логи (одна запись JSON на строку):

```bash
jq -c 'select(.level=="error")' app.jsonl | head -2
jq -r 'select(.level=="error") | .msg | gsub("[0-9]+"; "N")' app.jsonl | sort | uniq -c | sort -rn
jq -s 'map(select(.level=="error")) | first | {ts, msg}' app.jsonl
jq -s -c 'group_by(.level) | map({level: .[0].level, n: length})' app.jsonl
jq -r 'select(.ts >= "2026-11-15T11:40" and .ts < "2026-11-15T11:45" and .status == 500) | .ts' app.jsonl
```

Слежение вживую. `-n 0` показывает только новые строки, `--line-buffered` не копит вывод:

```bash
tail -n 0 -f app.log | grep --line-buffered " ERROR "
```

Остановка — Ctrl+C. В скрипте запускай в фоне и гаси по номеру процесса.

## Частые ошибки

- Чинят последнюю ошибку в логе, а она следствие. Сначала найди первую в окне.
- `grep -i error` ловит лишнее: `ConnectionRefusedError` внутри traceback, слово `errors=0`. Ищи по полю уровня: `" ERROR "`.
- Смотрят только `app.log`, а нужный час уже ушёл в `app.log.1.gz`.
- Время лога в UTC, а жалоба — по местному времени. Сдвиг в 3 часа уводит в чужое окно.
- `tail -f | grep | ...` без `--line-buffered` молчит минутами. Это буферизация, а не отсутствие ошибок.
- Одинаковые ошибки с разными номерами считаются разными. Заменяй числа на `N` перед `uniq -c`.
- Вывод «ошибок нет» по пустому `grep` в неправильном файле. Проверь, что лог вообще пишется: `tail -n 3`.

## След для Проверяющего

Положи в папку результатов задачи:

- `logs-summary.txt` — команды и их вывод: окно времени, число ошибок по типам, первая ошибка с номером строки.
- `logs-first-error.txt` — 10–20 строк контекста вокруг первой ошибки, без токенов и личных данных.
- `logs-after-fix.txt` — вывод слежения или счёта ошибок после исправления за тот же отрезок времени.
