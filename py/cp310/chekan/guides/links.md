## Что это и когда брать
curl (программа командной строки для HTTP-запросов) проверяет, что каждая ссылка открывается, и показывает код ответа и редиректы (переадресации). Тем же способом цитата сверяется с текстом первоисточника. Бери этот учебник для статьи, поста, рассылки, справки, юридического заключения — для любого текста со ссылками или цитатами. Не бери, когда ссылок и цитат нет. Не используй его для проверки страниц, где нужен вход в аккаунт: curl видит их как гость.

## Установка и проверка
```bash
curl --version | head -1
```
curl есть почти везде. Если нет — поставить пакетным менеджером, только после «да» пользователя.

## Порядок работы
1. Собери все ссылки из текста в файл, по одной на строку, без дублей.
2. Проверь каждую: код ответа, конечный адрес после редиректов, дату проверки.
3. Код 200 — ссылка жива. 301/302 — замени в тексте на конечный адрес. 404, 410, 5xx и ошибка соединения — ищи замену или убирай.
4. Каждую цитату и цифру найди на странице первоисточника дословно. Пересказ из вторых рук — не источник.
5. Рядом со ссылкой на нормативку, статистику или новость укажи дату обращения: «(дата обращения: 15.11.2026)».
6. Для важных источников проверь копию в веб-архиве: страница может измениться.

## Готовые команды
Собрать ссылки из текста:
```bash
grep -oE 'https?://[^] )>"]+' text.md | sed 's/[.,;:]$//' | sort -u > urls.txt
```
Быстрый взгляд на одну ссылку:
```bash
curl -sI --max-time 15 http://github.com/ | grep -iE '^(HTTP|location)'
```
Отчёт по всем ссылкам. Сохрани как `check_links.sh`:
```bash
printf 'url\tкод\tконечный_адрес\tредиректов\tдата_проверки\n'
while IFS= read -r url; do
  [ -z "$url" ] && continue
  res=$(curl -sS -o /dev/null -L --max-time 15 --max-redirs 5 -A 'Mozilla/5.0 link-check' \
        -w '%{http_code}\t%{url_effective}\t%{num_redirects}' "$url" 2>/dev/null) || res="ошибка\t-\t-"
  printf '%s\t%b\t%s\n' "$url" "$res" "$(date +%Y-%m-%d)"
done < "$1"
```
```bash
sh check_links.sh urls.txt > links-report.tsv; column -t -s "$(printf '\t')" links-report.tsv
```
Сверить цитату с первоисточником. Сохрани как `quote_check.sh`:
```bash
url=$1; quote=$2
curl -sL --max-time 20 -A 'Mozilla/5.0 link-check' "$url" \
  | sed -e 's/<[^>]*>/ /g' -e 's/&nbsp;/ /g' | tr -s ' \t\n' ' ' > page.txt
if grep -qiF -- "$quote" page.txt; then echo "НАЙДЕНО: $quote"; else echo "НЕ НАЙДЕНО: $quote"; exit 1; fi
```
```bash
sh quote_check.sh https://example.com/ "for use in documentation examples"
```
Есть ли копия в веб-архиве (только чтение, ничего не сохраняет):
```bash
curl -s --max-time 20 'https://archive.org/wayback/available?url=example.com'
```

## Частые ошибки
- Проверка только через `curl -I` (запрос HEAD). Часть сайтов отвечает на него 403 или 405, хотя страница открывается. Основная проверка — GET, как в `check_links.sh`.
- Код 200 на «мягкой 404»: сайт отдаёт заглушку «страница не найдена» с кодом 200. Сверяй заголовок или цитату страницы.
- Точка или скобка в конце ссылки попала в адрес, и ссылка «битая» по вине разбора.
- Цитата не найдена из-за ё/е, кавычек «» и "", неразрывного пробела. Ищи короткий уникальный кусок фразы.
- Сайт отдаёт текст через JavaScript, curl его не видит. Тогда открой страницу в браузере (учебник `playwright`) и сверяй там.
- Ссылка на поиск, личный кабинет или страницу с меткой сессии в адресе. У читателя она не откроется.
- Дата обращения не указана, а источник потом изменился.

## След для Проверяющего
