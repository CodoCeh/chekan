## Работа

Задачи делают участники команды — субагент `chekan-member`: свою роль он загружает сам по коду участника. Вы раздаёте задачи и следите за ходом, сами результат не делаете.

### Цикл одной задачи

1. `chekan task start NN`.
2. Запустите субагента `chekan-member` с моделью участника (`chekan team` покажет `model=` у каждого, передайте её параметром `model`). Первая строка промпта — `[chekan-executor NN]`, вторая — `Участник R3` (код исполнителя задачи). Дайте ему: задачу, чек-лист (`chekan task show NN`), пути к исходным файлам, папку результата в «Готово» и папку черновиков `.chekan/tmp/<прогон>/`. В конец брифа допишите вывод `chekan lessons brief <роль> --task "<текст задачи>"` — уроки роли по этой задаче.
3. Получили ответ «ВОПРОС: …» — спросите пользователя (`chekan ask "<текст>" --option ...`), ответ передайте исполнителю.
4. Запустите субагента `chekan-reviewer`. Дайте ему номер задачи, чек-лист и путь к результату. Он сам запишет `chekan check NN accept|return`. Вы этот вердикт поставить не можете: хук откажет.
5. Возврат на доработку — снова исполнитель, с причиной из вердикта. Потом снова проверяющий.
6. «Принято» — закройте: `chekan task done NN`. Результат, изменённый после проверки, закрыть нельзя.

### Параллель и отчёты

Не больше трёх исполнителей одновременно, волну запускайте одним сообщением. После каждой закрытой задачи или возврата, если пользователь просил отчёты «по каждой задаче», вставьте в чат `chekan progress`.
