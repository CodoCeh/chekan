## Что это и когда брать

v8unpack (утилита распаковки файлов 1С) превращает внешнюю обработку `.epf` или внешний отчёт `.erf` в папку исходников и собирает её обратно. Модули на языке 1С (`.bsl`) становятся обычным текстом: их можно читать, искать по ним и править. Программист 1С так вносит доработку. Аналитик 1С так узнаёт, какие объекты конфигурации трогает обработка.

Когда НЕ брать: правка самой конфигурации (`.cf`) или расширения (`.cfe`) — это Конфигуратор. Сборка ещё не доказывает, что код компилируется: для этого учебник `onec-check`.

## Установка и проверка

```bash
v8unpack --help
```

Если нет, ставят пакетом Python: `pipx install v8unpack`. Ставить что-либо — только после «да» пользователя.

## Порядок работы

1. Работай с копией. Исходный `.epf` не меняй и рядом не перезаписывай.
2. Распакуй копию в `src`. Не трогай `src` руками: это эталон для сравнения.
3. Скопируй `src` в `edit` и правь только `edit`.
4. Найди нужный модуль. `ExternalDataProcessor.obj.bsl` — модуль объекта (общий код обработки). `Form/<ИмяФормы>/Form.obj.bsl` — модуль формы (код кнопок и полей). Описание формы лежит в `Form.elem.json` рядом.
5. Перед правкой посмотри кодировку и концы строк. Сохраняй файл так же: UTF-8, BOM (метка `ef bb bf` в начале файла) — если была. В XML-выгрузке Конфигуратора модули всегда в UTF-8 с BOM и с концами строк CRLF.
6. Старый код не удаляй. Закомментируй его через `//` и напиши новый рядом. Обрами правку атрибуцией: `//+ Автор дата задача` перед правкой и `//- ...` после. Других комментариев не пиши.
7. Сделай round-trip (проверку туда-обратно): собери `edit`, распакуй результат и сравни с `edit`. Совпасть должно всё.
8. Сравни `src` и `edit`: разница — ровно твоя правка.

## Готовые команды

Распаковать и посмотреть, что внутри:

```bash
v8unpack -E sample.epf src
find src -type f | sort
head -c 3 src/ExternalDataProcessor.obj.bsl | xxd
cp -R src edit
```

Аналитику: какие объекты конфигурации упоминает код. Список проверь глазами: переменная с именем `Документы` тоже попадёт.

```python
import collections, pathlib, re
pat = r"(?:Документы?|Справочники?|РегистрСведений|РегистрНакопления)\.\w+"
hits = collections.Counter(m for p in pathlib.Path("src").rglob("*.bsl")
                           for m in re.findall(pat, p.read_text(encoding="utf-8-sig")))
for name, n in sorted(hits.items()):
    print(n, name)
```

Правка с сохранением кодировки и старого кода:

```python
from pathlib import Path
p = Path("edit/ExternalDataProcessor.obj.bsl")
raw = p.read_bytes()
bom = raw[:3] == b"\xef\xbb\xbf"
nl = "\r\n" if b"\r\n" in raw else "\n"
text = raw.decode("utf-8-sig")
old = "\tВозврат Строка(Номер);" + nl
assert text.count(old) == 1, "строка не найдена или встречается не один раз"
new = nl.join(["//+ Автор 15.11.2026 TASK-1", "\t//Возврат Строка(Номер);",
               '\tВозврат Формат(Номер, "ЧГ=");', "//- Автор 15.11.2026 TASK-1", ""])
p.write_bytes((b"\xef\xbb\xbf" if bom else b"") + text.replace(old, new).encode("utf-8"))
```

Собрать и сделать round-trip:

```bash
v8unpack -B edit out.epf
rm -rf back && v8unpack -E out.epf back
diff -r edit back && echo "round-trip чистый"
diff -ru src edit > change.diff; cat change.diff
```

`diff -r edit back` молчит — сборка ничего не потеряла. `change.diff` показывает только твою правку.

## Частые ошибки

- Правка оригинала вместо копии. Откатиться не к чему.
- Файл сохранён в Windows-1251 или с другими концами строк. Дифф показывает весь файл как изменённый.
- Сравнивают байты `.epf`. Сборка каждый раз даёт другие байты (время, сжатие). Сравнивай распакованные исходники.
- Старые строки удалены, а не закомментированы. Ревьюер не видит, что было.
- Правка не в том модуле. Похожая процедура есть и в модуле формы, и в модуле объекта, а вызывается только одна. Найди вызов через `grep -rn ИмяПроцедуры edit` до правки.
- `Form.elem.json` правят как текст. Скобки разъезжаются, форма не собирается. Правь через `json.load` и `json.dump(..., ensure_ascii=False)`.
- `grep -o` с русскими буквами зависит от локали (настройки языка системы). Он рвёт буквы или молча ничего не находит. Русские имена ищи через Python.
- Чистый round-trip принимают за проверку кода. Он доказывает только, что упаковка ничего не потеряла.

## След для Проверяющего

Положи в папку результатов задачи:

- Итоговый `.epf` или `.erf` с датой в имени.
- `change.diff` — разница `src` и `edit`.
- `roundtrip.txt` — вывод `diff -r edit back` и строку «round-trip чистый».
- Список изменённых модулей и процедур.
- Отчёт проверки по учебнику `onec-check`.
