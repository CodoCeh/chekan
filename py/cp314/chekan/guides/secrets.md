## Что это и когда брать

Секрет — ключ API, токен, пароль или закрытый ключ, по которому чужой человек получит доступ к сервису или деньгам. Утечка случается, когда секрет попадает в код, коммит, лог или публичный репозиторий. Проверку на секреты делают перед каждым коммитом, перед публикацией репозитория и перед передачей кода заказчику. Инструменты — `grep` по шаблонам ключей и `git log -p` по истории.

Когда НЕ брать: поиск багов и уязвимостей логики — это другая работа. Найденный секрет никогда не печатай целиком, даже в отчёт.

## Установка и проверка

```bash
git --version && grep --version | head -1
```

Обе утилиты есть в любой системе разработчика. Специальные сканеры (`gitleaks`, `trufflehog`) ищут лучше, но их ставят отдельно и только после «да» пользователя.

## Порядок работы

1. Проверь `.gitignore` (список файлов, которые git не отслеживает): в нём должны быть `.env`, ключи, выгрузки баз.
2. Просканируй рабочее дерево по шаблонам. Вывод маскируй, чтобы секрет не попал на экран и в логи.
3. Просканируй то, что идёт в коммит: `git diff --cached`.
4. Просканируй всю историю: удалённый файл остаётся в старых коммитах.
5. На каждую находку реши: настоящий ключ, тестовый пример или ложное срабатывание.
6. Нашёл настоящий ключ — сообщи пользователю и предложи порядок: отозвать ключ у поставщика, выпустить новый, положить его в `.env` или хранилище секретов, убрать из кода. Удаление файла без отзыва ключа не помогает: копия уже в истории, форках и кэшах.
7. Чистку истории (`git filter-repo`) и force-push делай только с «да» пользователя. Ключ всё равно отзывай.

## Готовые команды

Шаблоны и маска вывода:

```bash
PAT='AKIA[0-9A-Z]{16}|sk-[A-Za-z0-9_-]{20,}|ghp_[A-Za-z0-9]{36}|github_pat_[A-Za-z0-9_]{50,}|xox[baprs]-[A-Za-z0-9-]{10,}|-----BEGIN [A-Z ]*PRIVATE KEY-----|(password|passwd|secret|token|api_key)[[:space:]]*[:=]'
MASK='s/(AKIA|sk-|ghp_|github_pat_|xox[baprs]-)[A-Za-z0-9_-]+/\1****/g; s/((password|passwd|secret|token|api_key)[[:space:]]*[:=][[:space:]]*"?)[^"[:space:]]+/\1****/g'
```

`AKIA` — ключи AWS, `sk-` — ключи OpenAI и похожих, `ghp_` и `github_pat_` — токены GitHub, `xoxb-` — токены ботов Slack.

Рабочее дерево, индекс и история:

```bash
grep -rnIE --exclude-dir=.git --exclude-dir=node_modules --exclude-dir=.venv "$PAT" . | sed -E "$MASK"
grep -rlIE --exclude-dir=.git "$PAT" .
git diff --cached -U0 | grep -E '^\+' | grep -E "$PAT" | sed -E "$MASK"
git log --all -p | grep -nE "$PAT" | sed -E "$MASK"
git log --all --oneline -G 'AKIA[0-9A-Z]{16}'
git log --all --diff-filter=A --name-only --format="%h %s" | grep -E '\.env|\.pem|\.key|id_'
```

`-G` показывает коммиты, где строка с ключом появилась или исчезла. Последняя команда ищет файлы секретов, которые когда-либо попадали в историю.

`.gitignore` и проверка:

```bash
printf '.env\n.env.*\n!.env.example\n*.pem\n*.key\nid_*\n' >> .gitignore
git check-ignore -v .env
git rm --cached .env
```

Защита от случайного коммита — хук `.git/hooks/pre-commit` (скрипт, который git запускает перед коммитом), не забудь `chmod +x`:

```bash
#!/bin/sh
PAT='AKIA[0-9A-Z]{16}|sk-[A-Za-z0-9_-]{20,}|ghp_[A-Za-z0-9]{36}|xox[baprs]-[A-Za-z0-9-]{10,}|-----BEGIN [A-Z ]*PRIVATE KEY-----'
if git diff --cached -U0 | grep -E '^\+' | grep -qE "$PAT"; then
  echo "pre-commit: похоже на секрет в индексе, коммит остановлен" >&2
  exit 1
fi
```

Для пробы создавай поддельные ключи из заведомо фальшивых символов, например `AKIA` и `FAKEEXAMPLE00000`.

## Частые ошибки

- Файл с ключом удалили новым коммитом и считают вопрос закрытым. Ключ остался в истории. Его надо отозвать.
- `.env` добавили в `.gitignore` после коммита. Git продолжает его отслеживать, пока не выполнен `git rm --cached`.
- Находку печатают целиком в отчёт или чат. Это ещё одна утечка. Показывай только начало и файл со строкой.
- Сканируют только рабочее дерево. Публикация репозитория открывает всю историю и все ветки.
- `grep` без `-I` и исключений тонет в бинарниках и `node_modules`.
- Шаблоны ловят только известные префиксы. Пароль в `config.ini` или строка подключения к базе с паролем внутри ищутся отдельно, по словам `password`, `secret`, `://user:`.
- Тестовые ключи из документации поставщика принимают за утечку. Сверяй с примерами поставщика и уточняй у пользователя.

## След для Проверяющего

Положи в папку результатов задачи:

- `secrets-scan.txt` — команды и замаскированный вывод: дерево, индекс, история. Пустой результат тоже записывай.
- `secrets-findings.md` — таблица: файл и строка или коммит, тип ключа, вердикт (настоящий, тестовый, ложный), действие.
- Дифф `.gitignore`, если меняли. Сами значения ключей не прикладывай никогда.
